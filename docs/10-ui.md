# UI

Reference: the web Codex at chatgpt.com/codex. Task-first. A thread is the unit of work. Decided 2026-09-19.

## Vocabulary

| UI word | Meaning |
|---|---|
| Thread | a change set: worktree, branch, timeline, optional agent conversation |
| Home | composer plus task list |
| Review | an open PR touching markdown, opened in the review layout |
| Document | a markdown file, opened in Read or Editor |

## Screens

### Home
- Large composer at top: text box, KB picker, agent picker, Suggest/Edit toggle, @-mention docs, attach image.
- Submitting the composer creates a thread and opens it.
- Below: threads grouped by status. Running, Draft, In review, Changes requested, Ready to publish, Done (collapsed).
- Full sidebar visible.

### Thread
- Two columns. Sidebar collapses to an icon strip, reopens on hover or shortcut.
- Header bar: thread title, status pill, one primary action, overflow menu with Rename, Abandon, Open folder, Copy branch.
- Left column: timeline. Agent turns, tool calls with approve or deny inline, user saves as compact events, submit event, review comments mirrored from the PR. Composer at the bottom, same controls as Home minus the KB picker.
- Right column, tabs:
  - **Changes**: rendered block-aligned diff of the thread versus main. Per-file list at top. Default tab once anything changed. Agent edits pending acceptance show an Accept and Revert control per file.
  - **Editor**: live-preview editor. Tabs per open file. Files changed in the thread listed first.
  - **Read**: rendered document for reference, from the thread's worktree. Edit button moves it to Editor.
- Right column is resizable and collapsible.

### Primary action by status
| Status | Button |
|---|---|
| Draft, no changes | disabled |
| Draft, changes | Submit for review |
| In review | View review |
| Changes requested | View review |
| Approved, mergeable | Publish |
| Merged | Done, thread moves to Done group, worktree removed after 7 days |

### Review
- Dedicated layout. Diff full width, rendered, block-aligned, inline comment anchors on blocks.
- Right drawer, toggleable: PR conversation, comments in order, approvals, checks status.
- Header bar: PR title, author, status, Approve, Request changes, Merge, Open on provider.
- Full sidebar visible.
- Agent assistance in review is not in v1.

### Documents
- Sidebar section, folder tree from main, titles from frontmatter.
- Click opens Read in a document view with the full sidebar. Edit button: if a thread is selected in the sidebar, opens in that thread's Editor; otherwise creates a thread named after the document and opens it. Empty threads abandoned are deleted silently.

### Local changes
- If the main clone has uncommitted changes or is on a non-default branch, an implicit thread named Local changes appears at the top of Threads. Read-only in kmdn. Actions: Move to new thread (stash and apply into a fresh worktree), Adopt branch (register an existing branch as a thread, only for non-default branches). kmdn never commits in the main clone.

## Sidebar
- Top: KB switcher, search box that opens the palette pre-filtered.
- Sections, collapsible: Threads, Reviews, Documents.
- Threads: mine, active first, status pill on each, dot for unread events. Done group collapsed.
- Reviews: PRs where my review is requested first, then all open markdown PRs.
- Badges on section headers for counts needing attention.

## Composer controls
- Agent picker: detected agents, missing ones greyed with install link.
- Mode: Suggest (no writes), Edit (writes markdown and assets in the worktree, default), Developer (shell allowed with per-call approval). Developer visible only when enabled in settings.
- Model picker: only when the agent's adapter exposes a model list.
- @doc inserts a repo-relative path. Attach image copies into assets on send.

## Command palette
- Cmd-K. Searches documents, threads, reviews, actions, agents. Every action has a palette entry and a mouse path. Shortcuts shown in menus and tooltips.

## Notifications
- OS notification: agent needs approval, agent finished while window unfocused, review requested from me.
- Everything else: sidebar badges and thread dots.
- Per-event toggles in the Appearance dialog.

## First run
1. Sign in: GitHub or GitLab, device flow, or custom GitLab URL plus token.
2. Pick a repo from the list, paste a URL, or Open existing clone.
3. Choose a folder, default `~/kmdn/<repo>`.
Then Home. A non-blocking banner in the composer reports detected agents.

## Visual design
- Density and chrome from Codex: thin 1px borders, 6px radius, no shadows, one accent color, muted status colors.
- Reading panes get a wider measure and larger type than the sidebar and timeline.
- Light and dark, following the OS, manual override. Themes as token sets: Catppuccin (Latte, Frappé, Macchiato, Mocha), Nord, Gruvbox light and dark; per-device font and text size choices in an Appearance dialog (#77).
- Fonts: system UI or Inter for UI, JetBrains Mono for code.
- Stack: Tailwind, shadcn/ui components on Radix primitives, tokens customized. Components live in the repo.

## Layout at small widths
- Under 1100px inside a thread the right column becomes a toggle between timeline and Changes.
- Minimum window 900x600.
